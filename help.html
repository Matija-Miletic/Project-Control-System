Operating guide

Savannah Project Control

This edition runs entirely in your browser. It does not contact a server, ChatGPT, OpenAI or any other service.

Getting started

  1. Open index.html in Firefox, Chrome or Edge.
  2. Open Setup and confirm the project, status date, tasks and working calendar.
  3. Use Daily input for actual labour and physical progress.
  4. Use Programme to test daily labour allocations.
  5. Resolve critical Checks before exporting a report.
  6. Export a complete JSON backup at each reporting cycle.

Man-days

One man-day is one person working the configured productive day. The supplied system starts at 8.9 labour hours per man-day. Two people for one day therefore equal two man-days. Decimal entries such as 0.5 are allowed for planning.

Source allowances remain stored in labour hours. Changing the hours in one man-day changes the displayed planning equivalents; it does not rewrite imported source hours.

Programme grid

Every task row covers the complete project date range. Type a man-day value directly into any date. The typed cell becomes a fixed planning point and later automatic working days immediately redistribute the then-remaining task allowance to its target finish. A manual value of 0 deliberately blocks that day.

Automatic projections use Monday to Friday and skip calendar exceptions. Weekend and exception cells remain editable for deliberate work. Past weeks start collapsed; click a past week heading or use Toggle all past weeks to reveal them. The thin red column marks today.

Allocation view shows all values. Heatmap view emphasises concentration relative to assigned or practical crew. Manual view suppresses automatic placeholders so typed planning points are easier to see. Target and forecast lines are reversible overlays.

Reset future values

The red-outlined button at the top of Programme removes manual programme values strictly after today and clears task forecast overrides. It then restores the default weekday projections.

It does not delete history, today, daily progress, original allowances, approved variations, calendar rules or audit events. The action requires confirmation and is recorded in the audit trail.

Status date

The status date is the cut-off for actual project reporting. Daily entries cannot be later than it. Moving it forward should happen only after elapsed programme cells have been checked and actual labour is complete.

Daily input

Enter one record for each unique task, date, workfront and variation combination. Enter daily values, never cumulative totals. The system derives cumulative progress and forecast position.

Physical quantity completed

“Quantity” always means the task-specific unit shown beside that task: for example square metres, lineal metres, each, rooms or a defined weighted unit. It is not an undefined generic “unit”. Quantity must be measured consistently throughout the task.

Actual and earned hours

Actual hours are approved-scope labour entered up to the status date. Earned hours are the original/revised budget rate multiplied by completed physical quantity, capped at the approved quantity for calculation. A negative productivity variance means more labour has been spent than earned.

Forecast variance

Forecast variance is revised budget hours minus forecast total hours. Positive is within allowance; negative indicates an expected overrun. The forecast uses the budget rate until reliable progress reaches either configured threshold, then uses actual hours per completed physical unit unless a reasoned manual rate is present.

Materials

Link each material package to its controlling task. The suggested order date counts lead time plus buffer backwards from the required-on-site date using working days. Purchase-order date and supplier-confirmed delivery remain separate facts. “Off the shelf” is not a confirmed delivery.

Variations

Register exposure early. Submitted and exposure hours remain visible without changing approved task budgets. Only Approved or Partially approved records add their approved hours and physical units to the linked task.

Calendar exceptions

Enter a single date or an inclusive start/end range for weather, shutdowns, holidays, access delays or other non-working periods. Automatic programme values skip every date in the range. The range remains visible, editable and deletable in its collapsed register.

Task controls

Add Savannah-only tasks from Setup. User-created tasks can be fully edited and deleted once their linked operational records are removed. Imported baseline names, quantities, units and source hours are protected; their target dates, crew, workfront, status, criticality and forecast settings remain manageable.

Project settings

Status date, target finish, hours per man-day and forecast thresholds affect all calculations. Export a backup before a material change. Source hours are authoritative and are not recalculated from an hourly rate.

Checks

Critical checks identify conditions that make the project position unreliable or adverse. Warnings require review. Information items document explained conditions. Checks are recalculated from current data and do not replace project judgement or client programme validation.

Audit trail

Every write made through the interface creates a local audit event. Events are not editable through the UI and are included in the complete project backup. Importing an older backup intentionally restores that backup’s data and audit history.

Export and backup

Export CSV downloads the active page’s relevant data. Print / PDF opens the browser print dialog; choose “Save to PDF” for a PDF copy. Export project downloads the complete versioned JSON project, including all records and audit history. JSON is the restore format.

Local storage and isolation

The application first uses IndexedDB, the browser’s native structured database. If the browser blocks it for local files, the application falls back to browser storage and finally to temporary in-memory operation. The top status badge reports the active mode.

Browser data belongs to the current browser profile and can be erased by clearing browser data. It is not a substitute for project backups. Export JSON before moving computers, changing browser profiles, clearing storage or issuing a formal report.
